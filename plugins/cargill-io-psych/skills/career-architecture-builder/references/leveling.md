# Leveling — factors, ladders, and distinctness

## The four leveling factors (use across every family)

| Factor | Question it answers | Progression language (low → high) |
|---|---|---|
| **Scope** | How big is the unit of work owned? | Task → activity → project → program → sub-function → function → enterprise |
| **Complexity** | How ambiguous / novel / interdependent? | Defined & routine → variable → ambiguous → systemic/novel → strategic & shaping |
| **Autonomy / decision-rights** | How much is decided independently? | Works to instruction → general supervision → sets own approach → sets approach for others → sets direction/policy |
| **Impact** | How far do the consequences reach, and over what horizon? | Own output (days–weeks) → team (months) → program (1–2 yr) → function (2–3 yr) → enterprise (3–5+ yr) |

Optionally add **Influence / Communication** (informs peers → persuades
stakeholders → aligns leaders → shapes external/industry) if the org's framework
uses five factors. Keep the set fixed across families.

## Dual ladders (IC/expert vs people-manager)

Provide two parallel tracks with **equivalent levels** so deep experts advance
without managing people:

| Level of impact | IC / expert track | People-manager track |
|---|---|---|
| Builds own mastery | IC1–IC2 (learns, executes) | — |
| Drives team-scale results | IC3 (owns hard problems) | M1 (leads a team) |
| Drives program/function | IC4–IC5 (technical authority, sets approach for others) | M2–M3 (leads managers / a function) |
| Shapes enterprise | IC6+ (Fellow/Distinguished — shapes direction through expertise) | M4+ (executive) |

At equivalent levels the **level of impact is the same**; the tracks differ in
*how* impact is created — technical depth and authority vs people and operational
leadership. Pay bands at equivalent levels should align (that's the point of the
parallel ladder).

## Broadbanding

A broadband is a wide salary band spanning what used to be several narrow grades.
Architecture supports banding by making level boundaries meaningful: keep the
four-factor descriptors crisp so a band still maps to a defined scope/impact, not
a vague range.

## Distinctness rules (the failure mode to prevent)

- **No two adjacent levels may read the same on a factor.** If Level 3 and Level 4
  "Complexity" descriptors are interchangeable, the boundary is fictional.
- Each step up should change at least scope **or** complexity **or**
  decision-rights **or** impact in a way a manager could point to.
- Beware "inflation by adjective" (senior → highly senior → extremely senior).
  Use the progression *language* above, which names a different state, not a
  stronger adjective.
- Run a distinctness check: for each factor, read adjacent descriptors back to
  back; if you can't tell which is higher without the label, rewrite.

## Anti-patterns

- Family-specific factors (breaks cross-function equity and analytics).
- Tenure-based progression ("5 years in role → Level 4"). Progression is
  evidence of demonstrated scope/impact, not time served.
- Manager-only ladders (forces experts into management to advance — loses depth).
- Titles doing the work descriptors should do.

## Authority / alignment

Career architecture underpins pay structures, pay-equity analysis, workforce
planning, and people analytics — which is why factor consistency matters. Where
levels inform pay or exemption status, validate with Total Rewards and legal
(FLSA). This is an organizing structure, not a classification or pay decision.
